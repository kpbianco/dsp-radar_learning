## Independent review and repairs

Bounded read-only reviews covered governing scope and current state,
durable-test policy, lifecycle mathematics, association/lifecycle ordering,
confirmation and coast boundaries, deterministic geometry, resource ceilings,
rollback, learner isolation, and evidence claims. Their recommendations shaped
the explicit one-way promotion rule, delete-on-`L+1` boundary, truth-scoring
separation, nonrecycled IDs, exact baseline/sweep outcomes, and future-safe
tests. Audit repairs added real/integer/range validation in the MATLAB model,
corrected the conservative resource accounting to nine runs and 10,800 pair
slots, scored false confirmations by track-birth origin, gave the coast-sweep
figure separate unit-bearing axes, and made core lifecycle source tests
mutation-sensitive. A final educational-accuracy repair distinguishes the
unconditional `M`-of-`N` false-hit window probability from the `M-1`-of-`N-1`
probability conditioned on the birth hit. The final test audit reported no
remaining material findings; it also confirmed malformed manifest entries are
rejected while future compatible metadata is allowed and clarified that the
CLI timeout is a test hang guard rather than a product timeout path.

The independent system-risk review found that the existing one-to-one assertion
only observed the separated canonical record, where tracks never compete for a
report. It could therefore pass even if one report advanced two lifecycles. The
repair added a behavioral fixture with two active tracks inside one report's
gate and proves that only the nearest track receives the hit, confirms, and
coasts; the competing track records a miss and deletes at the tentative
boundary. No MATLAB source change was required because the explicit row/column
removal already satisfies that behavior.

The final review also found that the documented terminal-deletion invariant
had no behavioral fixture: the baseline never presents a later in-gate report
after a track deletes. A regression could therefore have returned deleted IDs
to association without failing the baseline and sweep tests. The repair adds a
delete-then-reappear record that proves the deleted ID receives no later
assignment, remains inactive, and the later report starts a fresh tentative ID
that must re-earn confirmation. Mutation-sensitive source bindings now retain
the active-at-scan-start filter and monotonic track-ID allocation. The shipped
MATLAB manager already satisfied the behavior, so no experiment change was
needed.
